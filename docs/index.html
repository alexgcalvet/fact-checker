fact-checker

A Chrome extension and a local helper that put fact checks, contradictions, fallacies and biases on top of a YouTube video, at the second they are said. This page describes the design of Step 1: one person, their laptop, recorded Spanish videos. Nothing is built yet.

What this is

A second, critical ear for YouTube: short flags on top of the video that point out inaccurate claims, self-contradictions, fallacies and biases, each with its evidence.

The problem

Fact-checkers in live interviews work in a hurry, with little context and no archive at hand, and the result can be poor. A viewer at home has no help at all: an error or a fallacy passes, and the conversation moves on.

The solution

A helper on the laptop reads the captions of a recorded video and analyses them with Claude, chunk by chunk, faster than playback. The extension shows each flag at the second of the words it quotes, with a confidence and a source.

Who it is for

In Step 1, one person who watches political interviews and debates in Spanish on youtube.com. Step 2 opens it to anyone through a shared server.

How it works

  2. Fetch the wordsyt-dlp gives the captions and the publish date.

  4. CacheFlags go into one file per video.

This is the whole journey of one recorded video, from the moment the person opens it to the moment a flag appears on the player. The helper works ahead of playback, so for the viewer it feels live, even though the video is analysed in advance.

How it works

  1. The person opens a video

    The extension reads the video id from the YouTube page and asks the helper to start an analysis. The person does nothing else: there is no button to press and no link to paste.

    src/extension/ · S1 · done

  2. The cache answers first

    If a finished flag file already exists for this video, the helper serves it at once. This keeps a second viewing free and instant, and it is the same idea that the shared cache of Step 2 relies on.

    src/helper/fact_checker/store.py · S1 · done

  3. The helper fetches the words

    The transcript adapter gets the captions with their timestamps and the publish date of the video. The date matters because every fact is checked against the data that was true on that day.

    src/helper/fact_checker/adapters/youtube.py · S1 · done

  4. The pipeline works chunk by chunk

    It starts at the second the person is watching: a first part of 30 seconds, then 2-minute parts forward, then the earlier part, up to 3 at once. Each part is ready before playback reaches it, and the helper logs by how many seconds.

    src/helper/fact_checker/core/ · S1 · done

  5. Claude finds and judges the claims

    For each chunk, Claude detects claims, guesses who said them, classifies a possible problem and gives a confidence. A contradiction is only flagged when the speaker is clear, because a wrong speaker makes a wrong flag.

    src/helper/fact_checker/adapters/llm_claude_cli.py · S1, S3 · planned

  6. Facts are checked against sources

    A factual claim is first searched among fact-checks already published by Maldita, Newtral and others. Only if none matches does Claude search the web, with official sources first.

    planned: src/helper/fact_checker/adapters/factcheck_google.py · S4 · planned

  7. The flag appears at its second

    The extension polls the helper while the video plays and shows each flag when playback reaches its timestamp. A contradiction appears at the second utterance, never before, so the viewer is never told about something that has not been said yet.

    src/extension/ · S1 · done

Why this way

  • Recorded videos first. The whole transcript is there before playback, so there is no latency pressure, it costs less and it is easy to test. Live streams come in a later step.
  • Analyse ahead, show on time. The viewer gets the live feel without the cost and risk of real-time streaming transcription.
  • A stream, not a batch. Each part is analysed with the text before it as context, so live streams later reuse the same pipeline with a live transcript.

Limits

  • A video with no captions gets no flags until the audio fallback with Whisper is built.
  • A long video can hit the budget. After 60 Claude tool calls per video-hour the run stops and the flag file says why.

The extension is what the person sees. It lives inside youtube.com, knows which video plays and at which second, and draws flags on the player. It holds no logic about claims: it only asks the helper for flags and shows them by their confidence.

How it works

  1. It runs inside youtube.com

    A content script, allowed by the Manifest V3 extension platform, runs on YouTube pages. It reads the video id and follows the playback time, including jumps forward and back.

    src/extension/ · S1 · done

  2. It asks the helper

    When a video opens, the extension asks the helper on localhost to start an analysis, then polls for the flags found so far. The helper address is one setting, which is all that changes in Step 2.

    src/extension/ · S1 · done

  3. It draws flags on the player

    A layer inside the player itself shows a small card in a corner at the flag's second: type, quote, confidence, source. Because the layer lives inside the player, it also works in full screen.

    src/extension/ · S1 · done

  4. It keeps doubtful flags aside

    Flags between 50% and 79% go to a collapsed side panel instead of the player. The person can still read them, but they never interrupt the video.

    src/extension/ · S5 · planned

  5. It marks the timeline

    Each flag gets a small mark on the progress bar. Clicking a mark jumps to the flag, which makes a long video easy to review.

    src/extension/ · S5 · planned

Why this way

  • An extension, not a web page, for Step 1. Only an extension can put flags on top of the real youtube.com player; an embedded player on another page may not be covered.
  • Two display levels. Precision on the player, without losing the doubtful flags. A single threshold or a user slider were the alternatives.

Limits

  • Desktop browsers only. The YouTube app on a phone or a TV cannot show anything from an extension.
  • YouTube can change its page. The overlay depends on the player's layout and may need a fix when YouTube updates it.

The helper is a small Python program on the laptop. Its core is the pipeline, which turns a transcript into flags and does no input or output of its own. Around it, two entry points start work, and a store keeps one flag file per video.

How it works

  1. The server takes requests

    A localhost HTTP server accepts two requests: start an analysis, and return the flag file so far. It listens on 127.0.0.1 only and accepts only the extension, so nothing on the network can reach it.

    src/helper/fact_checker/server.py · S1 · done

  2. The CLI runs the same pipeline

    analyze runs one video from the terminal, and eval runs the golden dataset and prints the score. Both call the same pipeline as the server.

    planned: src/helper/fact_checker/cli.py · S1, S2 · planned

  3. The pipeline turns words into flags

    It analyses one part of the transcript at a time, with the text before it as context: it detects claims, attributes each to a speaker, classifies it and gives a confidence. A live stream later feeds it the same way. It has no input or output of its own, which makes it easy to test and lets Step 2 run it on a server unchanged.

    src/helper/fact_checker/core/ · S1 · done

  4. A budget guard stops runaway runs

    The pipeline counts Claude tool calls. At 60 per video-hour it stops and writes the reason in the flag file, so a bug cannot exhaust the subscription.

    src/helper/fact_checker/core/ · S1 · done

  5. The store keeps one file per video

    Flags are appended as each chunk ends, so the extension can show early flags while the rest is analysed. The files live in ~/.fact-checker/, outside the repo, because they quote real people.

    src/helper/fact_checker/store.py · S1 · done

Why this way

  • A local helper on the subscription. No extra cost for one user; the Claude API would cost about €1–3 per video-hour.
  • Python. yt-dlp, Whisper and pyannote are Python libraries; an all-TypeScript helper would have to call them as outside programs.
  • A hard stop on tool calls. Every component declares its maximum cost, so a failure stays small.

Limits

  • The laptop must be on and the helper running for any new video to get flags.
  • Subscription usage limits per hour are not known yet; a heavy session could hit them.

Three adapters connect the pipeline to systems the project does not own: YouTube for the words, Claude Code for the judgement, and Google's index of published fact-checks for the evidence. Each adapter is one file, and none of their contracts is confirmed yet.

How it works

  1. Words and date from YouTube

    The transcript adapter uses yt-dlp to get the captions with timestamps and the publish date. If a video has no usable captions, a later slice downloads the audio and transcribes it locally with Whisper.

    src/helper/fact_checker/adapters/youtube.py, whisper.py · S1, S6 · planned

  2. Judgement from Claude Code

    The LLM adapter runs claude -p headless with a prompt and a JSON schema, on the person's own subscription. The pipeline never sees which model or account runs; it only gets structured answers.

    src/helper/fact_checker/adapters/llm_claude_cli.py · S1 · done

  3. Published fact-checks first

    Google collects the fact-checks that Maldita, Newtral, EFE Verifica and others publish in the ClaimReview format. The adapter searches them with two or three short phrasings of each claim, because the search matches words, not meaning.

    planned: src/helper/fact_checker/adapters/factcheck_google.py · S4 · planned

  4. The open web as a fallback

    When no published check matches, Claude searches the web. Official and primary sources such as INE, Eurostat, BOE and Banco de España come first; any other source lowers the confidence.

    S4 · planned

Why this way

  • Captions before audio. Captions are free and instant; transcribing every video would take minutes and more software.
  • Published fact-checks before web search. A match is high confidence, cites an accredited checker and costs nothing.
  • Data at the publish date. A claim that was true when it was said is not flagged as false later; a note shows the updated value instead.

Limits

  • Captions have no speaker. Claude infers who speaks from context; voice diarization is added only if tests show errors.
  • Some limits are unknown. Subscription usage limits and Fact Check API quotas are not documented, and web search returns no source date.

A noisy feed gets ignored, so precision comes first. The golden dataset is a set of invented Spanish dialogues with errors planted on purpose and the flags we expect. The eval command runs the real pipeline on it and prints precision and recall per flag type.

How it works

  1. A stronger model drafts the dialogues

    A more capable model than the one in the pipeline writes Spanish dialogues with planted contradictions, false data, fallacies and biases. Using a different, stronger model keeps the pipeline from grading its own homework.

    S2 · planned

  2. The person reviews them

    Each dialogue and its expected flags are checked by hand before they enter the dataset. This is what makes the dataset "golden": every expected flag is one a person agrees with.

    S2 · planned

  3. The eval runs the real pipeline

    fact-checker eval feeds each dialogue to the pipeline with the real LLM and compares the flags it finds with the expected ones.

    planned: src/helper/fact_checker/cli.py · S2 · planned

  4. It prints the score

    Precision and recall per flag type, so a change to a prompt shows at once whether it helped or hurt.

    planned: src/helper/fact_checker/cli.py · S2 · planned

Why this way

  • Synthetic, not real recordings. Conversations are personal data; real transcripts never enter the repo.
  • Precision over recall. A false flag costs more than a missed error, so the recall target is deliberately low.

Limits

  • Invented dialogues are cleaner than real talk. A good score on them does not prove the same score on a messy real interview.

The flag file is the one contract that every part shares: the pipeline writes it, the helper serves it as is, and the extension reads it. In Step 2 the web page and the report page read the same format, so it must stay stable.

Shared

Flags and contracts

The flag file, its fields and the two HTTP requests that serve it. Every flag quotes its words, names its type, gives a reason and a confidence; a factual flag names its source.

Flag
A short note on one utterance: the exact words, a type, a reason, a confidence and, for facts, a source. A signal, never a verdict on the speaker.
Confidence
How sure the pipeline is that a flag is right, from 0 to 1. It decides where the flag shows.
Helper
The Python program on the person's laptop that fetches captions, runs the analysis and serves flags to the extension.
Pipeline
The core of the helper: transcript in, flags out, with no input or output of its own.
Fallacy
A flaw in reasoning that makes an argument look stronger than it is, such as an attack on the person instead of the point.
Bias
A one-sided framing or selection of facts that tilts the conclusion.
Contradiction
The same speaker says two incompatible things in the same video.
ClaimReview
A standard web format that fact-checkers use to publish their verdicts. Google indexes it in the Fact Check Tools API.
yt-dlp
An open-source tool that downloads captions, metadata and media from YouTube.
claude -p
Claude Code run headless from a script: a prompt in, an answer out, on the person's own subscription.
Golden dataset
Invented dialogues with planted errors and the flags a person agrees they should get. The yardstick for quality.
Precision and recall
Precision: the share of shown flags that are right. Recall: the share of real errors that get a flag.
Manifest V3
The current format of Chrome extensions.
Step 1, Step 2
Step 1: one person, a laptop, no extra cost. Step 2: a shared server and cache, a web page and shareable reports for anyone.
